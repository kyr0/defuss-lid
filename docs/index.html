Extremely lightweight language identification

defuss-lid tells you which language a text is written in - even if it's very short. Pretrained fastText and Google CLD3 models are PQ-compressed into small language packs, and run in the browser, Bun or Node.js. Models are optimized by distinct character boosting and Direct Neural Optimization - Product Quantization (DNO-PQ).

Detected language

    Type or paste some text to identify its language.

    Scores are the models' native scores, not calibrated probabilities (fastText scores can slightly exceed 1). fastText models show their top 3; CLD3 returns only its top language with its reliable flag, which is cleared when the letters fit another language better. With the letter boost, fastText scores can reach 2 and CLD3 scores 21. A pack chooses among its own languages and never answers "none of these": Ukrainian text in der_3 comes out as Russian.

    Language packs

    Pick the smallest pack that covers your languages

    Each pack is one file, shipped in the npm package as defuss-lid/packs/<name> and published on Hugging Face. What your users download is the pack plus its runtime: fastText needs only a small JavaScript runtime, while CLD3 also loads a WebAssembly core, so its runtime is much larger. Each card adds both up and compares the pack with the same languages on the other runtime.

    How it works

    Two pretrained classifiers, one small file each

    No model was trained from scratch. defuss-lid reuses the released fastText lid.176 and Google CLD3 weights, keeps what a set of languages needs, and quantizes the rest. The two CLD3 packs then had their dense layers refitted on held-out text (DNO-PQ model card on Hugging Face (opens in a new tab)), so they make fewer errors than Google's original weights.

    fastText path

    Pure JavaScript, no WebAssembly: typed arrays and arithmetic.

    1. TokenizeSplit on ASCII whitespace and append the end-of-sentence token </s>. No case folding or Unicode normalization, exactly as the released model expects.
    2. Hash n-gramsCharacter 2- to 4-grams with < > word boundaries go through fastText's signed-byte FNV-1a hash into 2,000,000 buckets; a binary search finds the rows the pack kept.
    3. Look up PQ embeddingsEvery word and n-gram row is a product-quantized code; its 16-dimensional vector is rebuilt from shared codebooks, and all vectors are averaged.
    4. Int8 classifierThe average meets int8 classifier rows, each with its own FP32 scale.
    5. Hierarchical softmaxA binary tree of sigmoid decisions turns those into a score per language; a pack keeps only the decisions on the paths to its languages.

    CLD3 path

    Google's original feature extraction and network code, in WebAssembly, with DNO-PQ weights.

    1. Fetch the packA .cld3q file holds the output columns of its languages, product-quantized embeddings and int8 dense layers, refitted by DNO-PQ.
    2. Verify the shared corecld3-core.bin.gz is the CLD3 WebAssembly with its weights cut out (85.6 kB). The runtime checks the SHA-256 of the download and of the unpacked core before using it.
    3. Reconstruct the weightsPQ codes expand, int8 layers are dequantized, and every left-out output column gets a bias of −1e9; the tensors go back into the pinned 744,144-byte WebAssembly layout.
    4. Native inferenceCLD3's own feature extraction and network run unchanged and return the top language with a reliable flag.

    Letters as evidence

    Both models read letters statistically, so a short text can come out in a language whose alphabet it does not use: major_20 calls the Vietnamese «Kể từ» («since») Hindi. A table of 193 lines, one per language, lists the letters that set it apart (de äöüß, ru аийцщъыьэюяё); every other letter counts for all languages of its script. letterSupport turns that into the share of a text's letters each alphabet explains, predict(text) adds it, times a weight tuned on held-out text (1 for fastText, 20 for CLD3), to the model scores by default (boost: false turns it off), and CLD3's reliable flag is cleared when another language fits the letters better.

    Why the packs are small

    Output subsetting

    A pack keeps only what its languages need. For fastText these are the hierarchical-softmax decisions on the paths to the chosen labels, so each kept language keeps its original score. For CLD3 they are the chosen softmax columns.

    PQ + int8

    fastText packs reuse the released 8-group norm product quantizer unchanged and store classifier rows as int8. CLD3 packs product-quantize the three large embedding tables (4 groups × 256 centroids) and store dense layers as int8 with one scale per output neuron; DNO-PQ refits those layers after quantization, so the CLD3 packs beat Google's original weights.

    Feature pruning

    fastText subsets keep only the word and n-gram rows seen in 100 FLORES dev sentences per language. Accuracy is measured on separate FLORES devtest and MASSIVE test data; the pruning API rejects test and devtest records.

    Runtime once

    Pack sizes exclude the runtime. Every CLD3 pack shares one core, so a second CLD3 pack costs only its own bytes.

    Honest limits

    Size is not RAM

    CLD3 packs compress storage and transfer only. They rebuild the original WebAssembly with its dense kernels, so inference memory does not shrink.

    Pruning costs coverage

    Chinese is the largest observed failure: the pruned 20-language fastText pack falls from 88.70%/85.24% to 60.49%/44.92% on MASSIVE zh-CN/zh-TW. The recommended major_20 is CLD3, which keeps its shared feature tables.

    Short text is harder

    der_3 gets 100.00% of FLORES sentences right but 98.42% of their first 20 code points; for full the drop is 97.77% to 78.80%.

    Scores are not probabilities

    An allowlisted pack picks among its languages and does not reject others. To abstain, set a threshold you have measured on your own data.

    Use it

    Install once, identify anywhere JavaScript runs

    Every example on this page is executed by the project's end-to-end tests; the comment after each console.log is the exact output.

    1Install

    The package carries both runtimes and the four recommended packs. No runtime dependencies, no native addons.

    2Load a pack and predict

    Node.js 20.6 or newer resolves the node export condition, which reads the pack from the installed package. Run it with node detect.mjs.

    Bun uses the same disk loader as Node.js. Run it with bun detect.mjs.

    In the browser the same import resolves a fetch-based loader. It requests the pack from the package's models/ folder, relative to the module's URL, so your bundler or server has to serve models/ (and, for CLD3 packs, runtime/cld3-core.bin.gz) as assets. Serve the .gz file as plain bytes, without Content-Encoding: gzip: the runtime checks its hash and unpacks it itself.

    No install and no build: import the runtime from jsDelivr and load a model from the pinned Hugging Face revision.

    3CLD3 packs

    CLD3 packs run in WebAssembly and return only their top language, with CLD3's reliable flag, cleared when the text's letters fit another language better. Call dispose() when you are done.

    4Restrict the languages

    fastText models can rank only the languages your app supports. A restriction still picks one of them, so add a threshold on the model's own score (boost: false) to abstain.

    5Boost by alphabet

    Both runtimes add the letter evidence to the scores by default; CLD3 then marks a replaced answer as not reliable. Pass boost: false for the model's own scores.
